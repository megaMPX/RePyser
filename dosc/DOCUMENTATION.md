## 1. Назначение

`RePyser` — инструмент для первичного реверс-инжиниринга Python-программ. Проект ориентирован на анализ:

- отдельных файлов `.pyc`;
- исполняемых файлов, собранных через `PyInstaller`.

Программа помогает быстро получить декомпилированный код, дизассемблированный байткод, граф потока управления и короткий отчёт по потенциально подозрительным инструкциям.

## 2. Основные возможности

- открытие `.pyc` напрямую через графический интерфейс;
- распаковка `PyInstaller`-бандлов и просмотр найденных `.pyc`;
- декомпиляция через `pycdc`;
- дизассемблирование через стандартный модуль `dis`;
- построение CFG-графа для текущего code object;
- простой bytecode debugger с пошаговым исполнением;
- экспорт текстового отчёта в каталог `/reports`.

## 3. Как работает приложение

После запуска `main.py` открывает окно `PyQt6` и сразу предлагает выбрать файл из каталога `/samples`.

Если выбран `.pyc`, файл копируется во временную директорию и загружается напрямую. Если выбран `PyInstaller`-бандл, приложение использует `pyinstxtractor.py`, извлекает содержимое и показывает дерево найденных `.pyc`-файлов.

При выборе конкретного файла интерфейс выполняет четыре действия:

1. загружает `code object` через `marshal`;
2. строит дизассемблированный листинг через `dis.Bytecode`;
3. запускает `pycdc` для получения декомпилированного текста;
4. ищет подозрительные инструкции по списку ключевых слов и отображает CFG-граф.

## 4. Архитектура проекта

Основные части проекта разделены по ролям:

- `main.py` — точка входа, главное окно, открытие файлов, декомпиляция, экспорт отчёта;
- `src/constants.py` — сигнатуры и набор suspicious keywords;
- `src/file_utils.py` — базовая классификация `.pyc` по имени и содержимому;
- `src/pyinstaller_utils.py` — детектор `PyInstaller` по magic-байтам;
- `src/reporting.py` — сбор и форматирование отчёта по подозрительным инструкциям;
- `src/ui/code_editor.py` — редактор;
- `src/ui/syntax_highlighter.py` — подсветка кода и отчётов;
- `src/ui/graph_view.py` — построение и отображение CFG через `pydot/graphviz`;
- `src/ui/bytecode_debugger.py` — упрощённый отладчик байткода.

## 5. Структура репозитория

```text
RePyser/
├── main.py
├── Dockerfile
├── run.sh
├── rebuild.sh
├── requirements.txt
├── pyinstxtractor.py
├── src/
│   ├── constants.py
│   ├── file_utils.py
│   ├── pyinstaller_utils.py
│   ├── reporting.py
│   └── ui/
├── test_bin/
└── docs/
    └── DOCUMENTATION.md
```

`run.sh` подготавливает каталоги `samples/` и `reports/`, затем запускает контейнер с ограничениями: `read-only` rootfs, `tmpfs`, отключённая сеть, лимит памяти и процессов.

## 6. Запуск и сценарий работы

Базовый путь использования:

1. поместить исследуемые файлы в `samples/`;
2. запустить проект через `./run.sh`;
3. выбрать файл в диалоге открытия;
4. переключаться между вкладками `Decompilation`, `Disassembly`, `Graph`, `Report`;
5. при необходимости экспортировать отчёт через `Export report`.

При модификациях для пересборки контейнера используется `./rebuild.sh`.

- граф строится для текущего `code object`, а не для всего приложения целиком;
